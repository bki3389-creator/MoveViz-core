## 1. cloud 안 전문 정리 (채택 설계)

### 1-1. 승부 논리

이 코드베이스의 결정적 자산은 이미 심어져 있는 **픽셀-정합 데이터**다. `scene3d.js`의 모든 메시에 `userData = {roomId, kind: floor|wall|ceiling|furniture|light, wallKey, furnIdx}`가 태깅돼 있고, `getWalkPose()`가 걷다 멈춘 시점을 보존한다. 클라우드 안은 **① 미니BIM이 만든 기하학적 참값(GT) depth를 컨트롤로 보내고 ② 카탈로그 어휘로 프롬프트를 생성하고 ③ 같은 어휘로 추출해 돌아오는 폐쇄 루프**를 fetch 4번으로 완성한다.

### 1-2. 아키텍처와 데이터 흐름

```
[걷기 중 P키 / 캡처 버튼]  scene3d.js getWalkPose()
        │
        ▼
ai_capture.js ──┬─ beauty.png    현재 3D 래스터 스냅샷(재질 프리뷰 색)
                ├─ depth.png     scene.overrideMaterial 1패스 → 근거리=밝게(MiDaS 규약)
                ├─ segment.png   userData.kind별 플랫컬러 1패스 (벽/바닥/천장/가구/조명/개구부)
                └─ meta.json     {roomId, camPose, 보이는 객체 목록(kind·wallKey·furnIdx·화면bbox)}
        │
        ▼
ai_designer.js  대화 패널 (Claude claude-opus-5, 브라우저 직접 fetch
        │        + anthropic-dangerous-direct-browser-access 헤더, structured output)
        │        → 스타일 브리프 → {영문 프롬프트, 파라미터, 사용 카탈로그 어휘} JSON
        ▼
[생성 트랙 A: 최초 리스타일]   fal.run/fal-ai/flux-control-lora-depth
    depth.png(참값!) + 프롬프트 → 구조 고정 사실적 이미지  ($0.04/MP, 3~6초)
[생성 트랙 B: 대화식 반복 편집]  "소파만 가죽으로" →
    Nano Banana Pro(Gemini 3 Pro Image, $0.134/장) 또는 FLUX.1 Kontext [pro]($0.04/장)
    직전 결과 이미지 + 지시문 → 국소 편집, 나머지 보존  (전/후 슬라이더, shotModal 재사용)
        ▼
ai_designer.js  추출 호출: 최종 이미지 + segment.png + meta.json + 카탈로그 요약(id·명·spec)
    → Claude Vision structured output → §1-4 스키마 JSON
        ▼
ai_apply.js     changes[] → 적용 카드 목록 (항목별 승인, buildEstimate()로 전/후 견적 차액)
    → 승인 시 state.js 뮤테이션 (room.floorFinish/wallFinish/ceilFinish ·
      addLight/lightGridOf · replaceFurniture · addExtra · wallOverrides[wallKey])
    → emit('project') → 3D·견적·DXF·CSV 전부 자동 동기화
```

**핵심 설계 결정 3가지:**
1. **depth를 "추정"하지 않고 "소유"한다.** 경쟁 파이프라인은 사진에서 MiDaS로 depth를 추정하지만, 우리는 plan.json에서 빌드된 씬의 참값 depth를 렌더한다. 벽·개구부·가구 볼륨이 mm 단위로 정확 → 생성 이미지가 견적 대상 공간과 실제 일치.
2. **생성 어휘 = 추출 어휘.** 프롬프트 생성 단계에서 Claude가 카탈로그 항목의 영문 라벨만 쓰도록 강제(`fl_herring`→"herringbone oak flooring") → 추출 매핑 정확도가 구조적으로 상승.
3. **segment.png + meta.json이 역매핑 좌표계.** 추출 요소가 화면 어느 영역 → 어느 roomId·wallKey인지 픽셀로 확정 → "벽 z0만 파벽돌" 같은 벽 단위 적용(`wallOverrides`) 가능.

API 키: 설정 모달 입력 → localStorage(BYO-key). 배포 시 `serve.py`에 20줄 프록시(`/api/fal`, `/api/claude`)만 추가.

### 1-3. 뷰포인트 → 사실적 이미지 (GT depth 컨트롤)

**모델 선택 (2026-09 검증):**

| 용도 | 모델/엔드포인트 | 근거 · 가격 |
|---|---|---|
| 1차 리스타일(구조 고정) | `fal-ai/flux-control-lora-depth` | depth 컨트롤 공식 지원, GT depth 직접 입력. $0.04/MP, 3~6초 |
| 상위 품질 옵션 | `fal-ai/flux-pro/v1/depth` (BFL Flux Tools) | pro급 디테일, 동일 depth 입력 |
| 반복 국소 편집 | Nano Banana Pro (Gemini 3 Pro Image) | "지시한 것 외 전부 보존" 편집 최강. $0.134/장, 2~5초, 2K/4K |
| 저가 편집 대안 | `fal-ai/flux-pro/kontext` | 지시문 편집, $0.04/장 (비용 1/3) |

**컨트롤 전략:** depth 단독으로 시작(벽·개구부·가구 볼륨 고정엔 충분). 창문 프레임이 뭉개지면 2단계로 `fal-ai/flux-general`에 depth+canny 유니온(에지 = `EdgesGeometry` 라인 렌더 1패스, $0.075/MP). segment는 생성 컨트롤엔 쓰지 않고 추출 참조로만(MVP 절제).

**depth 렌더 함정 (선제 식별):** `scene.overrideMaterial` 1패스 → `readRenderTargetPixels` → near 0.1m / far는 방 대각선+2m 클램프 → **반전 필수**(ControlNet-depth는 MiDaS 규약: 가까울수록 흰색, three.js 기본은 반대). 반전 누락 시 공간이 뒤집힘 — node 단위테스트로 그라디언트 방향 검증.

**프롬프트 5슬롯 템플릿 (Claude가 대화 브리프에서 합성):**
```
[스타일] warm japandi living room, [재료=카탈로그 라벨] herringbone oak flooring,
lime-washed white walls, [조명] recessed downlights + warm indirect cove lighting
at dusk, [카메라] eye-level interior photograph, 24mm, f/5.6,
[품질] photorealistic editorial interior photography, no people
```
- Claude 디자이너 페르소나: 예산·취향·용도 3질문 후 무드 2안 제시 → 선택 시 프롬프트 JSON을 structured output으로 확정.
- 반복 편집: 한국어 요청을 영문 편집 명령으로 변환 — "change only the sofa to a cognac leather 3-seater, keep everything else identical".

### 1-4. 이미지 → 카탈로그 요소 매핑 (JSON)

Claude Vision 1콜. 입력 = 최종 생성 이미지 + segment.png + meta.json + 카탈로그 요약(`ALL_RATED`+`WORK_ITEMS`를 `{id,name,spec,unit}`로 자동 직렬화, 약 4K 토큰) + 현재 방 마감 상태. **`catalogId`는 enum으로 강제**(strict structured output) — 환각 id 원천 차단. 카탈로그에 없는 요소는 `unmatched`로 정직하게 분리.

  "style": { "name": "warm japandi", "palette": ["#E8DCC8","#B08A5E","#4A4A44"], "keywords": ["oak","limewash","indirect"] },

## 2. 낙선안 요약과 채택 아이디어

### 2-1. local 안 (ComfyUI 로컬 우선) — 6.5 / 7.0

**요지:** 브라우저 → 로컬 ComfyUI(127.0.0.1:8188, CORS 개방) + Claude API 3-프로세스. 패스트레이서 base 위 **img2img(denoise 0.5~0.65) + GT depth ControlNet(0.75~0.9) "이중 잠금"**으로 구조 유지·재질만 사실화. VRAM 티어 자동 선택(8GB SDXL / 12~16GB FLUX.2 klein 4B / 16~24GB FLUX.1-Depth-dev). 생성 무제한 0원, 세션당 Claude만 ~$0.23. 5일 MVP.

**낙선 사유(심사):** 최종 사용자 dGPU 8GB+·ComfyUI 설치·모델 3~13GB 전제가 무설치 정적 웹 배포 형태와 정면 충돌. 완화책이 "클라우드 API 폴백 어댑터"라 경쟁안을 자인. 국소 편집 모델 부재로 대화형 반복 일관성이 프론티어 편집 모델에 밀림. 코드 오기 2건(`emit('plan')`·`finishFloor` → 실제 `emit('project')`·`floorFinish`). 단 개발자 1인용 데모로는 유효(2위 근거).

**채택 아이디어:**
- **반복 경제학** — 회당 과금이 자유 반복을 억제한다는 지적은 유효 → cloud의 편집 트랙에 Kontext $0.04 저가 옵션을 기본 토글로 유지(심사 2 권고).
- **시드 규율** — 같은 대화 스레드에서는 시드 고정(재질만 미세 변화), "다르게 보여줘"에만 시드 랜덤 → 일관된 "그 방" 유지.
- **네거티브 고정부** — "cartoon, illustration, warped walls, extra windows, extra doors, distorted furniture, watermark".
- (장기 옵션) 완전 오프라인 요구 고객용 로컬 VLM(Qwen3-VL) 매핑 어댑터 여지.

### 2-2. hybrid 안 (3단계 점진) — 6.0 / 7.4

**요지:** 1단계 = 이미지 생성 API 없이 캡처+Claude Vision 대화 제안(즉시 출시) → 2단계 = Gemini/fal 리스타일 → 3단계 = 추출·매핑·plan 적용. 캡처 패킷(beauty/depth/segment + visibleSurfaces/Objects 매니페스트)이 전 단계 공통 입력. 매핑은 규칙 프리필터(≤10 후보) + Claude 재랭킹 2패스. 적용 후 **같은 camPose로 재렌더 → "AI 이미지 vs 적용된 실제 모델" 나란히 비교**.

**낙선 사유(심사):** 코드베이스 grounding이 가장 약함 — 카탈로그 id 체계 전부 가공(FUR-SOFA-0102·FIN-WD-SLAT-02·C-17, 실제는 fl_/wl_/w_ 체계), planRef 경로 가공, 공사항목 수 오류(43개 — 실제 WORK_ITEMS 75항목 체계), ES 모듈 앱에 플레인 `<script>` 통합 제안, RFC6902 패치 직적용이 기존 뮤테이터(pushHistory·폐기무게·emit)를 우회. 설계서대로 구현하면 적용 계층 재작업 필수. 이미지가 3~4주 뒤에나 나와 "결과물 사실성" 도달 최지연, 풀 세션 ~$1.0 최고가.

**채택 아이디어 (핵심 2건):**
- **1단계 즉시출시 전략 → §3 로드맵 1단계로 흡수.** 이미지 생성 없이 캡처+Claude Vision 제안 카드(카탈로그·견적 연동)만으로 먼저 출시하고 사용자 피드백을 받는 순서는 세 안 중 최고의 리스크 관리 — cloud 구현 순서를 이 구조로 재배열한다.
- **재렌더 대조 검증 루프** — 적용 후 같은 camPose 재렌더로 "AI 그림일 뿐"이라는 반론을 제품 안에서 스스로 반박. 3단계 완성 시 시연 킬러샷으로 채택.
- (참고) prompt caching으로 카탈로그 다이제스트·시스템 프롬프트 반복 턴 입력비 최대 90% 절감.

## 3. 구현 로드맵 (확정)

cloud 안의 설계(§1)를 hybrid의 점진 출시 구조로 재배열. 매 단계가 독립 출시 가능한 제품.

### 1단계 — 걷기 시점 캡처 + Claude Vision 제안 (이미지 생성 없이)
- `ai_capture.js`: 걷기 중 P키/버튼 → beauty/depth/segment 3패스 + meta.json (depth 반전 순수함수 + node 테스트).
- `ai_designer.js` + `#aiPanel`: Claude 대화(디자이너 페르소나) → **제안 카드**(카탈로그 id + `buildEstimate()` 차액 표시). 생성 API 0개, 과금은 Claude뿐.
- 산출 스키마는 §1-4의 부분집합으로 작성 → 3단계에서 그대로 재사용.
- 이 시점에 이미 "보고 → 대화 → 카탈로그·견적 연동 제안"이 완성된 제품.

### 2단계 — fal/Replicate ControlNet 리스타일
- 트랙 A: `flux-control-lora-depth`(GT depth 조건화) 1차 리스타일. 트랙 B: Nano Banana Pro / Kontext($0.04) 국소 편집 루프.
- shotModal 확장: 전/후 슬라이더, 히스토리 스트립, "이 시점 다시 생성".
- 프롬프트 어휘 = 카탈로그 영문 라벨 강제(§1-2 결정 2). 시드 규율·네거티브 고정부(local 채택분) 적용.
- 필요 시 depth+canny 유니온 승급, 생성 직후 구조 일치 검사 게이트.

### 3단계 — 요소 자동 반영
- `ai_apply.js`: Vision 추출(§1-4 스키마, enum 강제) → 카드 승인 → 기존 뮤테이터 경유 state patch → `emit('project')` → 3D·견적·DXF·CSV 자동 동기화.
- 재렌더 대조 검증 루프(hybrid 채택분): 적용 후 같은 camPose 재렌더 나란히 표시.
- 마무리: 헤드리스 스모크(mock 주입), `serve.py` 프록시 20줄(배포 모드).

**금기:** 자동 적용 없음(전 항목 승인제), catalogId는 enum 밖 생성 금지, 기존 뮤테이터 우회 금지(hybrid 감점 교훈), depth 반전 누락 금지.
