## 저장소

- 구조: `apps/web-minibim/` = 웹 미니BIM(참조용, 수정 금지) / `apps/ios/App/PlanShot/` = 네 작업 영역.

## 배경: 웹 미니BIM에 오늘(260902)까지 들어간 기능

웹(`apps/web-minibim/`)이 기능 선행 구현체이고 iOS는 이를 따라간다. 현재 웹 기능:

- **도면 편집**: 벽 스플릿(분할 도구), 끝단 그립 드래그, 벽/가구 드래그, 가벽 추가, 방 드래그 조립(자석 스냅)
- **문 종류**: 여닫이/미닫이 등 개폐방식(dk)·문짝(dm) 구분, 스윙 심볼
- **가구 라이프사이클**: 기존 가구 유지/폐기/교체(replaced) 상태 관리, 폐기 무게 자동 기록
- **견적**: 철거·가구까지 포함한 재료/노무 분리 내역(카탈로그 v3, 75항목 공사 체계), 노무 품(인·일) 환산, 인라인 단가 수정
- **DXF 내보내기**: 돋움(MST_DOTUM 계열) 텍스트·치수 포함 도면세트(단면+상세 포함)
- **CSV 내보내기**: 견적 내역
- **워크스루**: 1인칭 걷기(enterWalk/getWalkPose, 화각 70도)
- **렌더샷**: three-gpu-pathtracer 실사 렌더(걷기 시점 캡처, 220샘플), 재클릭 자가치유
- **조명 그리드**: 다운라이트 그리드 배치, 간접등, 천장 링(마이터)
- **마감 색 지정**: 방별 바닥/벽/천장 컬러피커(finishColors), 벽 마감 재질 표현, 가구 실사 재질

## iOS 현황

`apps/ios/App/PlanShot/` — 11개 파일:
`RoomScanView.swift`(RoomPlan 스캔), `ProjectsView.swift`, `ProjectDetailView.swift`, `RoomDetailView.swift`, `LayoutEditorView.swift`(도면·레이아웃 편집), `BOQEngine.swift`(견적), `BOQView.swift`, `BOQXLSXExporter.swift`, `PlanPDFExporter.swift`, `DXFExporter.swift`, `PSTheme.swift`

- 흐름 골격: 온디바이스 RoomPlan 스캔 → `plan.json` → 기본 도면 표시·견적 → PDF/xlsx/DXF 내보내기 + 레이아웃 편집기.
- **Mac에서 빌드 미검증 상태다.** Windows에서 작성돼 한 번도 Xcode 빌드를 통과한 적 없다고 전제하라.

## plan.json 스키마 — 웹과 동일성 유지 (최우선 계약)

방 하나의 plan 구조 (웹 `state.js`가 정본):

- `boundary`: 외곽 꼭짓점 배열 (직교 폴리곤, m 단위)
- `xw` / `zw`: 내부 가벽 (x방향/z방향)
- `openings[]`: `{ span, wall_dir, wall_pos, width, height, flip, dk, dm }` — dk=개폐방식(여닫이/미닫이 등), dm=문짝 구분
- `rooms`: 구역 정보
- `furniture[]`: `{ obb, existing, status, replaced, ... }` — obb=배치 박스, existing=기존 가구 여부, status=유지/폐기 등 라이프사이클, replaced=교체 정보
- `finishColors`: 방별 바닥/벽/천장 마감 색

**규칙: 모르는 필드를 만나면 절대 버리지 말고 그대로 보존해서 저장하라(라운드트립 보존).** 웹이 필드를 먼저 추가하는 경우가 많다. iOS가 이해 못 하는 키는 통과시키기만 하면 된다.

## 시킬 일 (우선순위 순)

1. **Xcode 빌드 통과** — 프로젝트를 열어 서명(개발 팀), 에셋 카탈로그, 타깃 설정 등 빌드를 막는 문제를 전부 해결하고 실기기 배포 가능 상태로 만든다. 컴파일 에러는 최소 수정 원칙(로직 재설계 금지).
2. **RoomPlan 스캔 → plan.json 라운드트립 실기기 테스트** — LiDAR 기기에서 실제 방 스캔 → plan.json 생성 → 다시 로드해 도면·견적이 정상 표시되는지, 저장→재로드 후 데이터 손실이 없는지 확인. 문제 지점과 재현 방법을 기록.
3. **웹과 plan.json 스키마 동일성 유지** — 위 스키마 절의 필드명·구조를 그대로 따른다. 새 필드는 임의로 추가하지 말고, 모르는 필드는 보존만 한다.
4. **웹 기능의 iOS 이식 (이 순서대로)** — ① 문 종류(dk/dm 편집 UI + 도면 심볼) ② 가구 라이프사이클(existing/status/replaced + 견적 연동) ③ 치수 입력(벽 길이·개구부 위치 수치 편집).

## 금지사항

- **plan.json 스키마 임의 변경 금지** — 필드 이름 변경, 단위 변경, 구조 개편 전부 금지. 필요하면 제안만 하고 멈춰라.
- **웹 코드(`apps/web-minibim/`) 수정 금지** — 읽고 참조하는 것만 허용.
- main 브랜치 직접 커밋 금지 — 작업은 `feat/planshot-flow`에서.
