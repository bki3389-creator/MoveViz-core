# 가구 인식률 진단 보고서 (2026-07-04)

멀티에이전트 검토 결과 (리더 4명 병렬 정독 → 진단 → 근본원인별 적대적 검증).
아래 근본 원인 6건은 **전부 코드·데이터로 재현 검증(CONFIRMED)** 된 것들이다.
기존 코드는 일절 수정하지 않았음 (이 보고서 파일만 신규 추가).

## 결론 한 줄

가구 인식률 저하는 모델(OWLv2) 성능 문제가 아니라 **① 입력 이미지가 망가진 채 들어가고
② 찾아낸 것도 필터 스택이 지우고 ③ 살아남은 것도 평면도에 잘못 그려지는** 3중 구조 문제다.

## 근본 원인 (전부 검증됨)

### 1. 검출기 입력이 시스템적으로 불량 — 90° 회전 + 모션 블러
- 세로로 스캔해도 키프레임은 ARKit 원본 가로 방향으로 저장되는데, `detect_furniture_vision.py`가
  OWLv2에 넣기 전에 바로 세우지 않음 → **검출기가 모든 변기/소파/침대를 옆으로 누운 상태로 봄**
  (`scans/20260628_130736/keyframes/kf_0010.jpg` 등에서 육안 확인).
- 실제 투입된 36뷰 중 25뷰가 블러 (Laplacian variance < 100, 중앙값 81). 캡처 앱은 이동량으로만
  스로틀하고, `fps_sample`(:338)은 카메라 위치로만 뷰를 뽑아 방향 다양성·선명도를 무시.
- 빌드 간 캡처 해상도 불안정 (320×240 × 6프레임짜리 스캔 존재 = 불량 빌드가 현장 배포된 증거).

### 2. 직렬 recall-killing 필터 9개+, 욕실 1개 스캔으로 튜닝
- score 0.20 → frontal 0.10 → min_views 2 → min_votes 0.5 → min_pts 40 → DBSCAN(13) →
  퇴화 필터 → SIZE_MIN_LONG → 공간 allowlist → NMS → 0.6m 병합 — 하나만 걸려도 삭제.
- **실제 사상자 확인**: 욕조 클러스터 실측 장변 0.97~0.99m인데 `SIZE_MIN_LONG['bathtub']=1.1m`
  (:56)에 걸려 후기 런에서 전멸 (초기 런 npts 1110~3383으로 잘 잡혔었음).
- 모든 임계값이 4.2㎡ 욕실 1개를 6번 재처리하며 튜닝됨 — 다른 공간 일반화 근거 없음.

### 3. 투표 기하 오류 3중
- (a) 마스크 없이 **2D 박스 전체**가 정점에 투표 → 뒤 벽/바닥 정점이 라벨 상속 (욕조 클러스터
  높이 2.08m 실측 = 벽까지 흡수), (b) per-vertex argmax → 큰 객체(책상)가 중첩 객체(의자 등)의
  정점을 전부 빼앗음, (c) 같은 카테고리 0.6m 병합 → 인접한 실제 의자들/쌍 세면대 삭제.

### 4. 융합 없음 + 실패 무음
- 키프레임이 있으면 비전 결과가 지오메트리 경로 결과를 **통째로 대체** — 비전이 놓치면
  지오메트리가 찾은 가구도 사라짐. `ingest_server.py:95-97`의 광역 except가 비전 단계 예외를
  삼켜서 **가구 0개 평면도가 무음으로 나감**.

### 5. 인식에 성공해도 평면도에 잘못 그려짐 (체감 인식률 하락의 숨은 주범)
- `_vision_to_plan_furniture`(:200-223)가 **yaw를 버리고** 축정렬 강제 + canonical 치수 스냅
  → 변기 yaw −82.3°가 축정렬 0.68×0.38로 전치되어 그려짐 (`scans/20260628_130736` plan.json 확인).
  올바른 검출이 "잘못 인식된 것처럼" 보임.

### 6. 지오메트리 경로 자체 상한
- 0.2㎡ 최소면적 필터가 스툴/선반/TV 전멸 (카테고리 재구성 0/7, 0/6, 0/5),
  불안정한 평면 경계 밖 후보점 하드 삭제 (경계 면적이 같은 스캔에서 6.76~54㎡로 널뜀).

## 평면화(floorplan) 쪽 발견 사항

- 경계 면적 불안정·과대 (dilate/erode+PAD 구조) — 가구 recall이 여기 체인으로 묶여 있음.
- structure/built-in/noise 분류기가 사실상 무필터 (out13.json 29/30이 structure) — README 스펙과 임계값 불일치.
- 경계 개선용으로 만든 `glb_floor_v5.tighten_boundary`가 **서버에 연결 안 된 채** 검증 스크립트에만 존재.
- `detect_openings`가 애매 셀을 window로 기본 처리, 1.5m 초과 개구부는 벽 취급 → 한국형 거실-주방
  통합 개구부(실측 3.3m)가 병합/차단됨.
- `IS_CAD` 라우팅(`mesh.faces < 2000`)이 저폴리 실스캔을 CAD 경로로 오분류.
- 15_floorplan_vectorize 트랙: watershed가 문 틈으로 누수(파우더룸 15.84㎡), OCR 10/15 — 상류 불안정.
- 벽선/코너 정확도는 한 번도 측정된 적 없음 (labels/ 비어 있음, score_walls.py 결과 없음).

## 권장 실행 계획

**Phase 0 (2~3일, 병행): 측정 루프부터.** 실제 방 3~5개 신규 스캔 + 수작업 라벨(카테고리+OBB)로
평가셋 구축 (지금은 욕실 1개×6런뿐). `ingest_server.py:95-97` except 표면화 + plan.json에
비전/지오메트리 가구 리스트 둘 다 기록 (실패 가시화, 비용 0).

**Phase 1 (3~5일, 기대 효과 최대): 입력과 명백한 유해 필터 수정.**
- 이미지 바로 세우고 박스 역회전 (~10줄, `detect_image`) — **단일 최대 기대값 변경**, 저장된
  109 키프레임으로 재스캔 없이 A/B 가능
- 블러 게이트(lapvar<60) + FPS 샘플링에 시선 방향 포함
- score 0.20→0.10, SIZE_MIN_LONG 삭제/반감 (욕조 복귀가 수용 기준), 병합을 footprint-IoU>0.3으로
- min_views를 인스턴스 레벨로, 공간 allowlist는 로그 전용으로 강등
- yaw 렌더링 수정 (`_render_furniture_topview`가 이미 쓰는 수식 재사용) + polygon 클램프
- iOS: maxDim 1024→1440, 캡처 시 선명도 게이트, 배포 빌드 확인

**Phase 2 (2~3주): 투표 기하.** SAM/MobileSAM 마스크 투표(벽 번짐 원천 제거), per-detection
인스턴스 형성(중첩 객체 생존), canonical 스냅은 검증용으로 강등, 평가셋으로 임계값 그리드 재튜닝.

**Phase 3 (2~3주, 중첩): 융합 레이어.** 내부 계획 문서 2개가 이미 처방한 구조 —
지오메트리 blob=제안, 비전=의미론, RoomPlan=제3 투표자, 전체 대체 금지. 가구를 평면 경계
불안정성에서 분리 (하드 삭제 → 플래그).

평면화 작업은 이 기간엔 가구를 막는 항목(yaw 주입, 경계 하드삭제, tighten_boundary 결정)으로
한정하고, 15_vectorize의 watershed/OCR은 스캔 트랙 안정화 후로 미루는 것을 권장.
